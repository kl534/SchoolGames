# SchoolGames

Mobile/tablet-first browser 3D games (TypeScript, Vite multi-page, three.js, cannon-es), deployed to GitHub Pages.

## Conventions

- TypeScript strict; Prettier (single quotes, width 100) and ESLint flat config. Before finishing
  run `npm run check` (format, lint, types, full tests, build; prints only failures). While
  working, run just the tests you touch: `npx vitest run tests/<file>.test.ts` or
  `npx vitest related --run <changed files>`. Random sweeps use `runs(full, quick)` from
  `tests/helpers/full.ts`.
- Each game has a `MAP.md`. Read it first, and update it when you add, remove or repurpose a file
  or dev hook. `npm test` fails if a `.ts` file in the game's folder is missing from it.
- Check by eye with `npm run shots -- <game-id>?<dev query> …`: one tiled sheet per state with
  all four sizes in `.shots/`. Reach hard states with the game's dev query hooks (`dev.ts`) instead
  of driving answers. Any game takes `?facts=<id>,<id>` in dev to open the round with those facts
  of the topic (e.g. `penalty-kick?topic=state-capitals&facts=missouri`).
- Shared code lives in `src/shared/` (scene, input, ui, assets, manifest, topics, progress, levels, round, feed, session, preview, results, audio, voice, answers, timers, tapflow, devfacts, pictures, hockey, levels-social, sync). Games import from there; never the reverse.
- Miss pictures: after a miss on a math fact (`fact.visual`) `tapFlow` shows a little animated picture of the sum above the green answer and counts it aloud (`src/shared/pictures/`; each miss shows the next way for that operation). Check them with the lab page (`npm run shots -- "/src/shared/pictures/lab.html?fact=add:8:5&way=add-join&at=3"`); any game takes `?picture=<way>|off` in dev. Count clips 1 to `MAX_COUNT` are in `sharedLines()`. A missing-number fact (`6 + ? = 12`) has `visual.blank`, and the picture's last line greens that operand (`statementParts`); the lab takes `blank=middle|first`.
- Maps: a fact with `map` is a US map (`kind: 'us-state'`, Find the state) or one continent of the world with the country lit (`kind: 'world'`, Find the country), shown as a big map in the middle of the screen. Games call `showFactMap(fact)` right after they put the prompt in the HUD (after `tapFlow.disarm()`) and `hideFactMap()` on an answer, a time-out and at the end; `tapFlow` brings it back on a miss with the right state green and the picked one red. Check it with the lab (`npm run shots -- "/src/shared/maps/lab.html?state=rhode-island&wrong=Connecticut"`; `view=thumbs` shows all 50 mini maps; `?country=italy` shows a country, `view=countries` all 60). `npm run maps` rebuilds `us-states-data.ts` (us-atlas) and `world-data.ts` (world-atlas) in `src/shared/maps/`.
- Flow: player picker → My Level (default home page, two paths with tabs, Math and Social Studies; the engine and Math levels are in `src/shared/levels.ts`) or a single topic (`src/shared/topics/`) → game. Games get `?topic=<id>`, which may be `my-level` (Math path) or `social-studies-level`, and must work for any topic (answers are strings, not just numbers). Add Social Studies levels by appending to `SOCIAL_STUDIES_LEVELS` in `src/shared/levels-social.ts` (and topics to `SOCIAL_STUDIES_TOPICS` in `src/shared/topics/social-studies.ts`). In My Level (either path) `session.topic` is synthetic: always call `answerOptions(session.topic, …)` so wrong answers come from the fact's own topic. `session.recordAnswer` saves under that real topic id; stars and high scores go under the path's id (`my-level` or `social-studies-level`).
- Every spoken line is a pre-recorded Kokoro clip in `public/voice/<key>.mp3`, where `key` is `voiceKey(text)` from `src/shared/voice.ts`; `speak()` falls back to the browser voice for a line without one. `src/shared/voice-lines.json` lists the lines and is generated by `npm run voice` (needs `uv`; it records only the missing clips). Commit the JSON and clips; `npm test` fails if either is out of date. Games and topics must not change fact text lightly: a changed line needs a new clip. If Kokoro says a name wrong, add its phonemes to `PRONUNCIATIONS` in `scripts/voice/generate.py` (the text and key stay the same) and run `npm run voice`, which re-records just the lines with that name.
- Progress is stored per player in localStorage under topic and fact ids, so never rename existing topic or fact ids. If facts must move to another topic, add a migration that copies their saved stats (see `migrateAboveTenTables` in `src/shared/progress.ts`).
- Games live in `src/games/<id>/` and are auto-discovered by `vite.config.ts` and the menu (`import.meta.glob`). Do not edit menu or config code to add a game.
- Use `import.meta.env.BASE_URL` for any absolute link; the site is served under `/schoolgames/`. Set `BASE_PATH` to change the base at build time (default `/`).
- Touch first: tap targets at least 48px, use pointer events (`src/shared/input.ts`), no hover-only interactions.
- Always `dispose()` the scene on `pagehide`.

## Add a game

1. Copy `src/games/penalty-kick/` to `src/games/<new-id>/` (id is lowercase kebab-case).
2. Edit `game.json` (`id` must equal the folder name; `title`, `description` required; `thumbnail` file name and `tags` optional; the menu card shows the thumbnail at 16:9, so replace the copied `thumbnail.svg` with a small picture of your game) and the page `<title>` in `index.html`. Write `MAP.md` for the game (copy the shape of `penalty-kick/MAP.md`).
3. Build the game in `main.ts` using `createScene`, `createPointerInput`, `createBackButton`/`createPauseOverlay`/`createMuteButton`, and `createAssetLoader`.
4. Learning loop: `startGameSession(id)` (redirect to `menuUrl()` if it returns null) → `session.chooseFacts()` → `showPreview()` → per turn `answerOptions()`, `fillAnswers()`, `speak(promptSpeech(fact))`, `session.recordAnswer()` → `createRound()` (or `createFactFeed()` for an endless run) handles retries → `showResults()` with `session.recordStars(starsFor(...))`. Bind the answers with `pressAnswers()`. After a miss call `tapFlow.reveal(buttons, options, fact, { chosen, … })` (`chosen` is the text of the wrong button picked, undefined on a time-out): it marks the green answer, reads the fact and waits for the tap. A fact's `wrongLines[chosen]` is read first (e.g. the trap city on State capitals); a game that reads the miss itself uses `...missSpeech(fact, chosen)` in place of `statementSpeech(fact)`. Delayed steps use `createTimers()` so they hold while paused. Honour `session.timerSecondsFor(fact)` (start the clock after the prompt is read). If the game speaks its own lines (callouts, score lines), build them in pure functions in `rules.ts`, list every possible one in `src/games/<id>/voice.ts` (`export const VOICE_LINES: string[]`, importing no DOM, three.js or `main.ts`), and run `npm run voice`. Open-ended lines (e.g. with a free-form number) can't be recorded; say something fixed instead.
5. `npm test` validates every manifest and folder layout.

## Add a topic

Add a `Topic` to `TOPICS` in `src/shared/topics/index.ts`, either generated (see `math.ts`) or from plain pairs with `listTopic(meta, items)`. Ids are lowercase kebab-case. `npm test` checks every topic is valid and can produce four distinct answer options. Then run `npm run voice` and commit the new clips and `voice-lines.json`; `npm test` fails otherwise.
